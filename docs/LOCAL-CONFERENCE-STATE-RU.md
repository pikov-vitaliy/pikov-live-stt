# Pikov LiveSTT: состояние контура и принятые решения

Срез: 16 августа 2026 г.
Первоначальная точка разработки: тег `v0.2.25`, commit `db78a58`.
База публичного fork после синхронизации: upstream commit `7772ad0e5264252ce0d62c525d008e6b6982f98a`.

Этот документ отвечает на два вопроса: **что работает прямо сейчас** и **почему сделано именно так**. Причины важнее описаний — большинство решений ниже выглядят произвольными, пока не знаешь, какое поведение сервера или браузера их вызвало.

Операционная инструкция: [LOCAL-CONFERENCE-TRANSCRIPTION-RU.md](LOCAL-CONFERENCE-TRANSCRIPTION-RU.md).
Полный перечень изменений: [LOCAL-CONFERENCE-TRANSCRIPTION-CHANGES-RU.md](LOCAL-CONFERENCE-TRANSCRIPTION-CHANGES-RU.md).

## Назначение

Запись видеоконференций и роликов, идущих **в браузере**, для последующего анализа: протоколы, погружение в контекст организации, разбор договорённостей. Записывающий — участник встречи, а не сторонний слушатель.

## Что проверено работающим

| Проверка | Как проверялось |
|---|---|
| Сервис распознаёт речь | Реальный речевой файл через `/v1/audio/transcriptions` — вернулся текст |
| Контейнер | `healthy`, порт опубликован только на `127.0.0.1:8001` |
| Расширение | 67 автотестов; публикационный прогон выполняется перед merge в `main` |
| Живая запись в файл | Подтверждена пользователем: текст доходит до `.md` |
| Микрофон | Подтверждён пользователем: голос попадает в запись |
| Пауза в потоке | Живой тест: 30-секундный разрыв, речь после него распозналась |

## Принятые решения

### Самостоятельное сопровождение в связанном fork

Апстрим (`QuentinFuxa/WhisperLiveKit`) используется как основа, а Pikov LiveSTT публикуется как именованный GitHub fork. Это сохраняет происхождение и облегчает получение исправлений upstream. Производные изменения сопровождаются независимо и не отправляются наверх автоматически; `compose.yml` и исходные профили не подменяются, локальный контур живёт в отдельных файлах.

### Разделения по спикерам нет и не планируется

Для задачи важен **общий контекст встречи**, а не то, кто именно произнёс фразу. Если когда-нибудь понадобится точная атрибуция, для этого будет использована другая платформа.

Следствия: диаризация выключена, пересобирать образ с `nemo-toolkit` не нужно, микрофон подмешивается в **общий канал** со звуком вкладки. Все реплики приходят как «Спикер 1», и экспорт в этом случае метку не ставит вовсе, чтобы не создавать ложного впечатления.

### Безопасность и обработка данных — общая ответственность

Технические ограничения по умолчанию — loopback-публикация сервиса, локальный ASR, выключенный микрофон и явный экспорт. Владелец контура дополнительно определяет правовое основание записи, уведомление участников, место и срок хранения, права доступа и удаление файлов. Документация фиксирует факты, необходимые для этих решений: что записывается, где сохраняется и сколько хранится.

### `--retention-seconds 300` остаётся

Апстрим предупреждает, что клиентам в режиме `full` ставить retention не следует. Здесь он всё же стоит, потому что без него сервер шлёт всю накопленную стенограмму на каждом обновлении: на двух часах это 400 КиБ двадцать раз в секунду против 17 КиБ сейчас. Потерю истории компенсирует локальный архив в расширении.

Плата за это решение — сдвиг времени начала у длинной незакрытой реплики, который приходится «сшивать» на стороне клиента (см. ниже).

### Пауза приостанавливает кодировщик, а не отбрасывает данные

Если просто перестать отправлять куски, `MediaRecorder` продолжит их производить, и в непрерывном потоке WebM образуется дыра — сервер не сможет декодировать дальше, и после «Продолжить» распознавание уже не восстановится.

### Перед паузой скармливается 6,5 секунды тишины

Chromium **вычитает** длительность паузы из шкалы записи (`MuxerTimestampAdapter` накапливает `total_time_in_pause_` и вычитает его из меток кадров). Сервер паузы поэтому не видит совсем. А закрывает он реплику только по тишине дольше пяти секунд, измеренной в звуковом времени (`audio_processor.py:28,322`).

Без обходного решения реплика, открытая на момент паузы, оставалась бы открытой и вбирала первые слова следующего фрагмента — то есть разбивка файла по роликам сломалась бы. Поэтому звук глушится мгновенно, а кодировщик ещё несколько секунд пишет цифровую тишину, после чего останавливается.

### Очистка экрана скрывает часть текста реплики, а не реплику целиком

Сервер дописывает всё сказанное **в одну открытую реплику** с неизменным временем начала. Скрыть реплику целиком нельзя — пропадёт новая речь (файл пишется, экран пуст). Показать целиком тоже нельзя — вернётся старый текст.

Поэтому запоминается, сколько символов каждой реплики уже было показано, и дальше выводится только добавленное. Убранное не возвращается: кнопки «показать скрытое» намеренно нет — очистка нажимается осознанно.

### Экран — витрина, файл — хранилище

Ни очистка экрана, ни что-либо ещё в интерфейсе не удаляет текст из архива, `.md` и автосохранения. Единственное удаление, доступное пользователю, — явная кнопка «Удалить навсегда» в блоке восстановления.

### Микрофон опционален и по умолчанию выключен

Для просмотра роликов он не нужен, и просить доступ незачем. Включается галочкой; разрешение запрашивается один раз со страницы расширения, потому что браузер не показывает такой запрос из фонового документа.

Микрофон идёт **только в дорожку записи** — в динамики по-прежнему подаётся один звук вкладки, иначе пользователь слышал бы себя. Оба источника идут с запасом по громкости и через лимитер: сумма двух источников на полной громкости клиппирует, а обрезанный звук распознаётся заметно хуже.

На паузе микрофон физически отключается (`track.enabled = false`), а не просто перестаёт записываться.

> Разрешение выдано **расширению**, а не конференции. Отключение микрофона в самой конференции запись расширения не останавливает.

### Живой файл принадлежит одной встрече

Дескриптор выбранного `.md` отвязывается по завершении сессии. Иначе следующая встреча подхватывала бы его автоматически и переписывала файл предыдущей — запись всегда переписывает файл целиком, дописывания нет (политика распознавания правит уже выданный текст, и дописывание оставляло бы устаревшие фразы).

### `/health` не считается доказательством работоспособности

Он отвечает `ready=true`, как только модель загружена в память, и продолжает так отвечать после того, как распознавание сломалось. Ровно это произошло 16.08.2026 при обновлении драйвера NVIDIA без перезагрузки.

Поэтому перед встречей запускается [scripts/check-conference-service.ps1](../scripts/check-conference-service.ps1): он прогоняет через сервис реальный речевой файл и отдельно смотрит журнал на следы отказов инференса.

### После обновления драйвера NVIDIA — `wsl --shutdown`

Проверено: `wsl --terminate docker-desktop` **не помогает**, виртуальная машина WSL продолжает держать библиотеки старого драйвера. Помогает полная остановка `wsl --shutdown`, после которой Windows проецирует библиотеки заново. Перезагрузка Windows не потребовалась.

## Открытые вопросы

| Вопрос | Состояние |
|---|---|
| Эхо при прослушивании **из динамиков** | Не проверено на живой встрече. Эхоподавление включено; в наушниках проблемы быть не должно |
| Microsoft Edge | Используются совместимые Chromium API, но отдельный живой Edge-тест ещё не проведён |
| Формальный WER-бенчмарк | `large-v3` работает, но сравнительный замер на разрешённой выборке русскоязычных встреч ещё не выполнен |

## Чего в контуре нет

- **Сквозного поиска и индекса по встречам.** Каждая встреча — отдельный `.md`, связи между ними нет. Для цели «анализировать все встречи» это следующий естественный шаг.
- **Словаря терминологии.** Флаги подсказки (`--init-prompt`, `--static-init-prompt`) заведены только на политику `simulstreaming`, а здесь используется `localagreement`. Без правки серверного кода не подключить.
- **Сохранения самого аудио.** Пишется только текст; переслушать или перераспознать запись нельзя.
- **Автовозобновления захвата вкладки.** Контейнер использует
  `restart: unless-stopped` и возвращается после запуска Docker Desktop, если
  его не остановили вручную. Но браузерный захват всегда начинается явным
  кликом по иконке: восстановление вкладок Chrome само запись не возобновляет.
- Захвата системного звука и настольных клиентов — только вкладка браузера.
