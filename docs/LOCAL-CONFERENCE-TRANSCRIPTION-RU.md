# Pikov LiveSTT: локальная транскрипция видеоконференций на Windows

Это рабочая инструкция Pikov LiveSTT. На исходной машине репозиторий расположен в `V:\WhisperLiveKit`; в другом клоне замените этот путь на свой. Инструкция позволяет после перезагрузки Windows самостоятельно запустить сервис, начать новую транскрипцию во вкладке Chromium-браузера и сохранить результат.

```text
Вкладка Chromium-браузера с Контур.Толком
  -> расширение Pikov LiveSTT (аудио вкладки + опциональный микрофон)
  -> ws://127.0.0.1:8001/asr
  -> Docker Desktop + NVIDIA GPU
  -> боковая панель браузера
  -> копирование Markdown или файл .md
```

Сервис опубликован только на `127.0.0.1:8001`: аудио и распознавание остаются на данном компьютере, внешний ASR API не используется. Не меняйте привязку порта на `0.0.0.0` или адрес локальной сети. В текущей версии WLK это не является безопасной сетевой публикацией даже при заданном API-токене.

## Быстрый старт после перезагрузки компьютера

Контейнер настроен с `restart: unless-stopped`: после запуска Docker Desktop он
возвращается автоматически, если ранее не был остановлен вручную. Перед каждой
встречей всё равно выполните проверку ниже; она также безопасно запустит сервис,
если автозапуск не состоялся.

1. Запустите **Docker Desktop** из меню «Пуск» и дождитесь, пока он перейдёт в состояние Running.

2. Откройте PowerShell и выполните:

   ```powershell
   Set-Location -LiteralPath 'V:\WhisperLiveKit'
   docker version
   docker compose -f compose.conference.local.yml up -d --wait
   docker compose -f compose.conference.local.yml ps
   Invoke-RestMethod http://127.0.0.1:8001/health
   ```

3. Нормальный результат: в `ps` контейнер `whisperlivekit-conference` имеет статус `healthy`, а последний запрос возвращает JSON с `"status":"ok"`, `"backend":"faster-whisper"` и `"ready":true`.

   **Внимание: `ready=true` сам по себе ничего не гарантирует.** Он означает лишь, что модель загружена в память, и продолжает отвечать `true`, даже когда распознавание полностью сломано. Именно так выглядела поломка 16.08.2026: `/health` был зелёный, а каждый вызов падал с `CUDA failed with error unknown error`.

   Поэтому перед встречей запускайте настоящую проверку — она прогоняет через сервис реальный речевой файл и смотрит журнал:

   ```powershell
   pwsh -File scripts\check-conference-service.ps1
   ```

   Она заканчивается либо «сервис действительно распознаёт речь», либо списком проблем с готовыми командами. Ненулевой код возврата означает, что начинать встречу нельзя.

### Если распознавание молчит, а сервис выглядит здоровым

Самая частая причина — **обновление драйвера NVIDIA без перезагрузки Windows**. У уже работающего контейнера при этом обесценивается CUDA-контекст (в журнале `CUDA failed with error unknown error`), а новый контейнер вообще не стартует с ошибкой `nvidia-container-cli: initialization error: WSL environment detected but no adapters were found`.

Лечится без перезагрузки Windows, но важно сделать именно **полную остановку WSL**, а не перезапуск отдельного дистрибутива:

```powershell
wsl --shutdown
```

Это проверено 16.08.2026: `wsl --terminate docker-desktop` **не помогает** — виртуальная машина WSL продолжает жить и держит спроецированные библиотеки старого драйвера. `wsl --shutdown` останавливает её целиком, и при следующем запуске Windows проецирует библиотеки уже нового драйвера.

Порядок действий:

```powershell
wsl --shutdown
# дождаться, пока Docker Desktop поднимет движок заново (полминуты-минута)
Set-Location -LiteralPath 'V:\WhisperLiveKit'
docker compose -f compose.conference.local.yml up -d --wait
pwsh -File scripts\check-conference-service.ps1
```

`wsl --shutdown` закрывает все дистрибутивы WSL — сохраните работу в них заранее. Если и это не помогло, остаётся `Restart-Service LxssManager -Force`, а затем перезагрузка Windows, которая чинит гарантированно.

4. Откройте вкладку Контур.Толка в Chrome или Brave и нажмите значок **Pikov LiveSTT** именно в этой вкладке. Откроется боковая панель и начнётся новая транскрипция.

Старый захват вкладки после перезагрузки Windows, перезапуска Chrome или перезагрузки расширения не восстанавливается. Восстанавливать вкладки Chrome недостаточно: для каждой новой встречи снова нажимайте значок расширения.

## Как провести встречу и сохранить стенограмму

1. Убедитесь, что звук конференции слышен в наушниках или колонках. Расширение всегда захватывает **звук выбранной вкладки**, а микрофон добавляет только при включённой галочке. Звук остальных приложений и всего компьютера не захватывается.
2. Нажмите иконку расширения в этой вкладке. Оставьте адрес сервера `ws://127.0.0.1:8001/asr`.
3. Панель можно закрыть, переключиться на другую вкладку или кликнуть вне неё: захват и распознавание продолжаются в фоновом документе Chrome. Повторный клик по иконке в той же вкладке только снова откроет панель.
4. По окончании нажмите **«Остановить транскрипцию»** и дождитесь завершения обработки последнего аудиофрагмента.
5. В боковой панели используйте кнопки:

   - **«Формат»** — «Диалог» (по умолчанию, сплошной текст абзацами), «С таймкодами» или «Простой текст»;
   - **«Копировать всё»** — стенограмма текущей сессии в буфер обмена в выбранном формате;
   - **«Сохранить .md»** — Chrome скачает файл вида `2026-08-16 14-05 Контур.Толк.md` в обычную папку загрузок браузера;
   - **`A−` / `A+`** — уменьшают или увеличивают только текст стенограммы; выбранный размер сохраняется в профиле браузера.

Экспорт берёт накопленные реплики за всю текущую сессию, а не только последние 300 строк, показанные в панели. Если экспорт сделан до окончания обработки, Markdown явно помечает его как промежуточный и помещает текущую меняющуюся фразу в отдельный раздел.

### Запись выборочно: пауза и продолжение

Кнопка **⏸ Пауза** останавливает запись, не разрывая сессию: вкладка остаётся захваченной, соединение живым, файл сохраняет всё, что уже записано. Кнопка превращается в **▶ Продолжить**.

Это рассчитано на сценарий «смотрю подряд, записываю выборочно»: открыт один файл на весь сеанс, а в него попадают только отмеченные фрагменты. Каждое «Продолжить» открывает в файле новый раздел с временем и названием вкладки на тот момент:

```markdown
### 20:10 — Разбор инцидента с утечкой
### 20:41 — Настройка SIEM: практика
```

**⏹ Завершить** — полный останов, как раньше: отпускает вкладку и закрывает сессию. **🧹 Очистить экран** убирает текст только с экрана; архив и файл не трогаются.

### Запись собственного голоса

По умолчанию расширение пишет только то, что **воспроизводит** вкладка, то есть собеседников. Ваш голос идёт в конференцию, а не из неё, и в стенограмму не попадает.

Галочка **«Записывать мой микрофон»** это исправляет. При первом включении откроется вкладка с разовым запросом доступа — разрешение выдаётся один раз.

Практические замечания:

- поставьте галочку и выдайте доступ **до** встречи: во время неё лишний запрос отвлекает;
- выбор применяется со следующего запуска захвата, менять источник посреди записи нельзя;
- расширение берёт свой поток с микрофона, поэтому одновременная работа конференции с тем же микрофоном ему не мешает;
- в наушниках качество лучше: из динамиков реплики собеседников попадают обратно в микрофон, и хотя эхоподавление включено, полностью полагаться на него не стоит.

> **Отключение микрофона в самой конференции не останавливает запись расширения** — это независимые вещи. Чтобы гарантированно ничего не писалось, нажмите **⏸ Пауза** (микрофон отключается) или **⏹ Завершить**.

### Копирование отдельных фраз

Текст в панели можно выделять мышью прямо во время речи. Кроме того:

- наведите на реплику — справа появится кнопка **«Копировать»** для этой одной фразы;
- **двойной клик** по реплике копирует её сразу;
- **Ctrl+клик** добавляет реплику к выделению, после чего внизу появляется **«Копировать выбранное»**;
- прокрутка вверх отключает автопрокрутку — вернуться к живому тексту можно кнопкой **«↓ Новые реплики»**.

### Живой файл на диске

Кнопка **«Писать в файл…»** предлагает выбрать `.md` в любой папке — удобно класть его сразу к материалам конкретной встречи. Дальше расширение переписывает этот файл по ходу разговора: его можно держать открытым в VS Code и видеть, как появляется текст. Папку можно менять от встречи к встрече, браузер запомнит последнюю.

Во время каждой записи рядом ненадолго возникает служебный файл `.crswap` — так Chrome заменяет содержимое целиком. Это нормально и исчезает само.

Если Chrome не разрешит запись из фонового документа, файл будет обновляться только пока открыта панель. Статус под кнопкой прямо об этом сообщит.

### Если встреча оборвалась

Стенограмма автоматически сохраняется в профиль браузера раз в 15 секунд и переживает перезапуск Chrome и перезагрузку Windows. При следующем открытии панели появится предложение **«Восстановить»** или **«Удалить»**. Такие копии удаляются сами через 7 дней, хранится не больше 10 последних.

Это страховка, а не архив: долговременный результат по-прежнему создаётся явным **«Сохранить .md»** или живой записью в файл. Буфер обмена также может быть доступен истории буфера или синхронизации ОС — для конфиденциальных встреч безопаснее сохранить файл в разрешённое локальное хранилище.

Во время активного захвата на иконке расширения горит значок `REC`: видно с любой вкладки, что запись идёт.

## Первый запуск и обновление расширения

Расширение уже лежит в `V:\WhisperLiveKit\chrome-extension`. Для загрузки или обновления:

1. Откройте `chrome://extensions` (в Brave — `brave://extensions`).
2. Включите «Режим разработчика».
3. Если расширения ещё нет, выберите «Загрузить распакованное» и укажите `V:\WhisperLiveKit\chrome-extension`.
4. Если оно уже было загружено, нажмите **«Обновить»** на карточке расширения.

После изменения файлов расширения нужно именно нажать «Обновить». Это останавливает текущий захват; сначала сохраните нужную стенограмму. Скрипт `scripts/sync_extension.py` относится к устаревшему popup-интерфейсу и для текущей боковой панели не нужен.

## Управление Docker-сервисом

Все команды выполняются из корня проекта:

```powershell
Set-Location -LiteralPath 'V:\WhisperLiveKit'
```

| Задача | Команда |
|---|---|
| Запустить и дождаться готовности | `docker compose -f compose.conference.local.yml up -d --wait` |
| Проверить статус | `docker compose -f compose.conference.local.yml ps` |
| Проверить HTTP-готовность | `Invoke-RestMethod http://127.0.0.1:8001/health` |
| Посмотреть последние события | `docker compose -f compose.conference.local.yml logs --tail 200` |
| Смотреть журнал в реальном времени | `docker compose -f compose.conference.local.yml logs -f --tail 100` |
| Остановить, сохранив контейнер | `docker compose -f compose.conference.local.yml stop` |
| Пересоздать и запустить после изменения параметров | `docker compose -f compose.conference.local.yml up -d --force-recreate --wait` |
| Пересобрать образ после изменения Dockerfile/зависимостей | `docker compose -f compose.conference.local.yml up -d --build --force-recreate --wait` |
| Удалить контейнер, но оставить кэш моделей | `docker compose -f compose.conference.local.yml down` |

Не используйте `docker compose down -v`, `docker volume rm whisperlivekit_wlk-hf-cache` или широкую очистку Docker с томами, если хотите сохранить уже загруженные модели. Именованный том `whisperlivekit_wlk-hf-cache` содержит кэш весов.

Дополнительная проверка, что сервис не опубликован в сеть:

```powershell
docker port whisperlivekit-conference
```

Ожидаемая привязка — `127.0.0.1:8001`, а не `0.0.0.0` и не IP-адрес локальной сети.

## Постоянные настройки модели

Стартовый профиль уже задан в `compose.conference.local.yml`:

- `faster-whisper` с политикой `localagreement`;
- русский язык `ru`;
- модель `large-v3` (требует примерно 10 ГиБ свободной видеопамяти);
- локальный порт `8001`;
- серверное хранение последних пяти минут для ограничения памяти.

Если нужно изменить модель, язык или режим офлайн, создайте в корне проекта файл `.env` через `notepad .env`:

```dotenv
WLK_PORT=8001
WLK_MODEL=large-v3
WLK_LANGUAGE=ru
# Включать только после того, как эта модель уже однажды скачалась:
# WLK_OFFLINE=1
```

Файл `.env` исключён из Git. После изменения сохраните его и пересоздайте контейнер:

```powershell
docker compose -f compose.conference.local.yml up -d --force-recreate --wait
```

`WLK_OFFLINE=1` запрещает загрузку весов из Hugging Face. Не включайте его при первой загрузке или при выборе новой модели. Если `large-v3` окажется слишком требовательной к VRAM или задержке, можно временно задать более быстрый компромисс `WLK_MODEL=large-v3-turbo`, затем провести реальную проверку качества и задержки на незасекреченной записи.

## Если что-то не работает

| Симптом | Действие |
|---|---|
| `docker version` не показывает раздел Server | Docker Desktop ещё не готов; дождитесь Running и повторите команду. |
| `health` не отвечает | Выполните `docker compose -f compose.conference.local.yml logs --tail 200`; убедитесь, что запущен именно порт `8001`. |
| В панели нет текста | Проверьте `health`, затем убедитесь, что иконка была нажата в вкладке конференции и в ней действительно есть звук. |
| Панель закрылась | Это допустимо: откройте её повторным кликом по иконке расширения в той же вкладке. |
| Перезапустили Chrome или Windows | Запустите Docker-сервис по разделу «Быстрый старт», затем нажмите иконку расширения ещё раз; старая сессия не возобновится. |
| Нужен текст, но встреча ещё идёт | Нажмите «Копировать всё» или «Сохранить .md»; результат будет отмечен как промежуточный. |
| Нужна запись вашей речи | До запуска встречи включите «Записывать мой микрофон» и выдайте расширению разрешение. Микрофон смешивается с аудио вкладки в один канал. |

## Границы и защита данных

- Это автоматическое ASR, а не заверенная стенограмма: перед распространением проверяйте текст, термины и атрибуцию спикеров.
- Расширение не захватывает настольное приложение Толка и не переключается на
  микрофон как на резервный источник. Микрофон подключается только явной
  настройкой пользователя и смешивается со звуком вкладки.
- Локальная обработка не отменяет обязанностей по уведомлению участников, основаниям обработки ПДн и внутренней политике организации. До рабочих встреч согласуйте сценарий с владельцем данных, ИБ и юристами; для защищаемой информации задайте срок хранения, доступ и порядок удаления Markdown-файлов.
- Ограничение публикации на loopback, отсутствие облачного ASR и явный пользовательский экспорт реализуют принцип минимизации данных и наименьших привилегий. Для корпоративного внедрения дополнительно проведите SCA/SBOM и проверку лицензионных условий зависимостей и весов в рамках процессов РБПО по ГОСТ Р 56939-2024.
