# Текущее состояние локального PoC и отличия от исходного WhisperLiveKit

Дата среза: 16 августа 2026 г.  
Исходная точка: тег `v0.2.25`, commit `db78a58f3dc02528cf989f7be827d0ff248873dc`.  
Статус: все описанные изменения находятся только в локальном рабочем каталоге `V:\WhisperLiveKit`; коммит и отправка в удалённый репозиторий не выполнялись.

Этот документ фиксирует именно локальный PoC для транскрибации аудио вкладки видеоконференции. Операционная инструкция на следующий запуск находится в [LOCAL-CONFERENCE-TRANSCRIPTION-RU.md](LOCAL-CONFERENCE-TRANSCRIPTION-RU.md).

## Результат

Из исходного универсального репозитория получился локальный контур для браузерной встречи:

```text
Вкладка Контур.Толка в Chromium-браузере
  -> расширение захватывает только звук этой вкладки
  -> ws://127.0.0.1:8001/asr
  -> Docker Desktop + NVIDIA GPU + Whisper large-v3
  -> живая боковая панель браузера
  -> явное копирование или сохранение Markdown-стенограммы
```

В текущем состоянии сервис действительно работает: контейнер `whisperlivekit-conference` имеет статус `healthy`, а `/health` отвечает `status=ok`, `backend=faster-whisper`, `ready=true`. В нём загружена модель `faster-whisper/large-v3`.

## Реализованная архитектура

### Локальный сервис ASR

Добавлен [compose.conference.local.yml](../compose.conference.local.yml). Он намеренно не меняет upstream `compose.yml`, чтобы стандартные профили репозитория остались доступными отдельно.

Особенности локального профиля:

- использует NVIDIA GPU и образ с Linux/CUDA-зависимостями (`cu129`);
- публикует порт только на loopback: `127.0.0.1:${WLK_PORT:-8001}:8000`;
- запускает `faster-whisper` с политикой `localagreement` — этот флаг обязателен, поскольку один только `--backend faster-whisper` не гарантирует отказ от политики SimulStreaming;
- фиксирует язык `ru` и базовую модель `large-v3`;
- сохраняет веса Hugging Face в томе `whisperlivekit_wlk-hf-cache`, поэтому пересоздание контейнера не требует повторной загрузки модели;
- отключает telemetry/implicit token Hugging Face и сетевую загрузку warm-up WAV (`--warmup-file ""`);
- оставляет на сервере только 300 секунд последних сегментов, чтобы память процесса не росла во время длинной встречи.

Текущий процесс внутри контейнера слушает `0.0.0.0`, но это ограничено контейнерной сетью. Снаружи Docker он доступен только на `127.0.0.1:8001`. Это принципиальное ограничение безопасности: встроенная конфигурация WLK не является безопасным опубликованным в LAN API.

### Расширение для Chromium-браузеров

Активный путь обработки выглядит так:

```text
Нажатие иконки расширения в вкладке встречи
  -> background.js получает tabCapture stream ID выбранной вкладки
  -> background.js создаёт offscreen.html и открывает sidepanel.html
  -> offscreen.js получает поток вкладки и передаёт его CaptureSession
  -> CaptureSession сохраняет пользователю слышимость через AudioContext
     и отправляет WebM-чанки в локальный WebSocket /asr
  -> WLK отдаёт живые обновления
  -> sidepanel.js отображает их и ведёт локальный архив финализированных реплик
```

Расширение захватывает аудио выбранной вкладки и, если включена соответствующая галочка, микрофон (см. второй заход ниже). Системный звук Windows, настольные клиенты и звук других программ оно не захватывает.

Для этого механизма требуется Chromium 116+ (`minimum_chrome_version: 116`). Код рассчитан на Chrome и совместимые Chromium-браузеры. В Brave он уже загружался; совместимость с Edge ожидается по тем же API, но отдельный live-тест в Edge ещё не проводился.

### Устойчивость, архив и экспорт

Сервер WLK удерживает лишь пять последних минут. Поэтому добавлен `TranscriptArchive`: он накапливает приходящие `lines`, заменяет пересмотренные сервером сегменты и не архивирует меняющийся `buffer_transcription`. Благодаря этому экспорт не ограничен 300 секундами сервера или 300 строками, показанными в панели.

> **Поправка от 16.08.2026.** Ранее здесь утверждалось, что архив «принимает только завершённые `lines`». Это неверно: `whisperlivekit/tokens_alignment.py:285-286` кладёт последним элементом `lines` ещё не закрытую реплику, а закрывается она только при паузе дольше `MIN_DURATION_REAL_SILENCE = 5` секунд (`whisperlivekit/audio_processor.py:26,292`). Из этого следовала порча экспорта, описанная в разделе «Исправления от 16.08.2026».

Кнопки работают так:

- **Копировать Markdown** — формирует полную Markdown-стенограмму и кладёт её в буфер обмена. Для этого добавлено точечное permission `clipboardWrite`.
- **Сохранить .md** — создаёт Blob и инициирует обычное скачивание браузером. Permission `downloads` не запрашивается.
- После штатной остановки последняя стенограмма временно хранится в `chrome.storage.session`, чтобы её можно было открыть повторно в той же сессии браузера. После перезапуска Chrome/Windows эта копия исчезает; постоянный результат создаётся только явным сохранением `.md`.

Формат экспортируемого Markdown содержит время начала/завершения/экспорта в UTC, статус финализации, источник аудио, число реплик и отдельный раздел для незавершённой фразы. В нём есть предупреждение, что это автоматическая транскрипция и перед распространением нужно проверить текст и атрибуцию спикеров.

### Исправление ошибки при остановке

Во время теста в Brave при нажатии «Остановить транскрипцию» возникали ошибки `Cannot read properties of undefined (reading 'session')` и `Illegal invocation`. Причина: offscreen-контекст обращался к `chrome.storage.session`, который в этом контексте Brave не предоставил ожидаемым образом.

Теперь offscreen-документ только сообщает service worker о начале и завершении сессии. `background.js`:

1. удаляет предыдущую временную стенограмму только после успешного запуска новой сессии;
2. сначала сохраняет завершённый снимок в `chrome.storage.session`;
3. только потом закрывает offscreen-документ;
4. при ошибке сохранения не закрывает источник и показывает понятную ошибку в панели.

Это исправление проверено автоматическими тестами. Оно ещё требует короткой ручной проверки после обновления установленного в Brave/Chrome unpacked-расширения.

### Крупный шрифт

В боковую панель добавлены кнопки `A−` и `A+`. Они изменяют только текст транскрипта:

- исходное значение — 18 px;
- минимальное — 14 px;
- максимальное — 28 px;
- шаг — 2 px;
- значение хранится в `chrome.storage.local`, поэтому сохраняется между сессиями браузера.

## Исправления и доработки от 16.08.2026

### Порча экспорта на длинной встрече

Сервер держит реплику открытой, пока не обнаружит паузу дольше 5 секунд (`audio_processor.py:26,292`), а `_prune` обрезает открытой реплике голову, как только она перерастает `--retention-seconds 300` (`tokens_alignment.py:110`). Одна и та же речь поэтому приходила снова с изменившимся `start`, а дедупликация в `TranscriptArchive` опиралась именно на `start` — и подшивала ещё одну копию на каждом обновлении.

Замер на часовой встрече без пятисекундных пауз: 826 записей в архиве и 619 500 слов в экспорте при 9 000 фактически произнесённых, то есть каждая фраза повторялась около 69 раз.

Исправлено сшивкой по перекрытию текста (`stitchTruncatedText`, префикс-функция): фрагмент с обрезанной головой дописывается к уже накопленной реплике. При отсутствии доказуемого перекрытия обе строки сохраняются раздельно — алгоритм не достраивает текст догадками. После исправления: 1 запись, все слова по одному разу.

Убрать `--retention-seconds 300` было нельзя: без него сервер шлёт всю стенограмму на каждом обновлении, и на двух часах это 400 КиБ двадцать раз в секунду (7,8 МиБ/с) против 17 КиБ сейчас.

### Производительность панели

`TranscriptArchive.merge` фильтровал весь архив и пересортировывал его на каждую входящую строку. Замер (окно 75 строк, 20 обновлений в секунду): 26 мс процессорного времени на секунду речи через 5 минут встречи и 522 мс через два часа, причём дважды — в offscreen и в панели. Переписано на индекс по времени начала с бинарным поиском и быстрым выходом для неизменившихся строк: 1-2 мс независимо от длительности встречи.

### Потеря стенограммы при переключении вкладки

`CaptureSession.start` вытеснял активную сессию через `finish(..., false)`, то есть по единственному пути, который пропускал сохранение, после чего очищал архив; `background.js` вдобавок удалял предыдущий снимок при старте новой сессии. Один клик по иконке на другой вкладке уничтожал час работы. Добавлен обратный вызов `onPreempted`: стенограмма передаётся на сохранение до очистки, а удаление снимка при старте убрано.

### Кнопка «Остановить» гасла при ошибке

`publishError` рассылал поддельный снимок состояния `idle`, хотя захват продолжался; панель отключала кнопку без возможности вернуть её иначе как переоткрытием панели. Ошибка теперь передаётся отдельным типом сообщения и состояния сессии не трогает.

### Панель

- Точечная перерисовка вместо полной пересборки DOM 20 раз в секунду — текст стало возможно выделять мышью во время речи.
- Автопрокрутка отключается при прокрутке вверх, возврат — кнопкой «↓ Новые реплики».
- Копирование отдельной реплики: кнопка при наведении, двойной клик, мультивыбор по Ctrl+клик.
- Вёрстка переведена на flex-колонку вместо `calc(100vh - 250px)`, убравшего двойные полосы прокрутки на узкой панели.
- `aria-live` снят с контейнера транскрипции: при 20 обновлениях в секунду он делал панель непригодной для чтения с экрана.

### Экспорт

- Экранирование сокращено до необходимого: `&<>` и inline-конструкции Markdown. Скобки, тире и даты больше не превращаются в `\(3 человека\)`.
- Формат «Диалог» по умолчанию: абзацы вместо списка, таймкод при смене говорящего, метки «Спикер 1» не ставятся, если говорящий один. Форматы «С таймкодами» и «Простой текст» доступны в списке.
- Локальное время вместо UTC, имя файла из заголовка вкладки: `2026-08-16 14-05 Контур.Толк.md`.

### Сохранность

- Автосохранение в `chrome.storage.local` раз в 15 секунд, восстановление при следующем открытии панели, автоочистка через 7 дней.
- Живая запись в выбранный `.md` через File System Access: файл можно держать открытым в редакторе. Пишет offscreen-документ, поэтому запись продолжается при закрытой панели; при отказе — запасной путь через панель с явным статусом.
- Значок `REC` на иконке расширения во время активного захвата.

Тесты расширения: было 18, стало 51.

## Второй заход 16.08.2026: выборочная запись и микрофон

### Выборочная запись одной сессией

Сценарий: человек смотрит ролики подряд в одной вкладке, пишет только некоторые, и хочет один файл на весь сеанс.

- **⏸ Пауза / ▶ Продолжить** останавливают и возобновляют запись, **не разрывая сессию**: вкладка остаётся захваченной, соединение живым, файл сохраняет уже записанное.
- **⏹ Завершить** — прежний полный останов.
- **🧹 Очистить экран** убирает текст с экрана насовсем, не трогая архив и файл.
- Каждое «Продолжить» открывает в файле фрагмент с временем и заголовком вкладки на тот момент: `### 20:41 — Настройка SIEM`.

Два неочевидных места, найденных до написания кода:

1. **Нельзя выбрасывать куски данных на паузе.** `MediaRecorder` продолжит их производить; если их не отправлять, в непрерывном потоке WebM образуется дыра и сервер не сможет декодировать дальше. Приостанавливать нужно сам рекордер. Безопасность разрыва во времени подтверждена живым тестом: 30-секундная пауза посреди потока, речь после неё распозналась.
2. **Chromium вычитает длительность паузы из шкалы записи** (`MuxerTimestampAdapter` накапливает `total_time_in_pause_` и вычитает его из меток кадров). Сервер паузы не видит вовсе, а реплику он закрывает по тишине дольше 5 секунд, измеренной в звуковом времени. Без обходного решения первые слова следующего фрагмента попадали бы в раздел предыдущего. Поэтому при паузе звук глушится сразу, но кодировщик ещё 6,5 секунды пишет цифровую тишину — сервер её слышит и закрывает реплику.

Очистка экрана тоже упирается в поведение сервера: всё сказанное дописывается в одну открытую реплику с неизменным временем начала. Скрывать реплику целиком нельзя (пропадёт новая речь), показывать целиком тоже (вернётся старый текст). Поэтому запоминается, какая часть текста каждой реплики уже была показана, и дальше выводится только добавленное.

### Микрофон

Захват вкладки записывает только то, что вкладка воспроизводит. Голос пользователя идёт во вкладку, а не из неё, и в стенограмму не попадал вовсе — то есть в записи были все, кроме владельца записи.

- Галочка «Записывать мой микрофон», разовый запрос доступа через `requestPermissions.html` (браузер не показывает такой запрос из фонового документа).
- Микрофон подмешивается **только в дорожку записи**; в динамики по-прежнему идёт один звук вкладки.
- Оба источника идут с запасом по громкости и через лимитер: сумма двух источников на полной громкости клиппирует, а обрезанный звук распознаётся заметно хуже — гипотезы перестают совпадать и текст не подтверждается.
- На паузе микрофон физически отключается (`track.enabled = false`), а не просто перестаёт писаться.
- Отказ в доступе или отсутствие устройства не срывают запись: она продолжается без микрофона.

> Разрешение выдаётся расширению, а не конференции. Отключение микрофона **в самой конференции** запись расширения не останавливает.

### Проверка сервиса, которая не врёт

`/health` отвечает `ready=true`, как только модель загружена, и продолжает так отвечать после того, как распознавание сломалось. Именно так выглядел отказ 16.08.2026: обновление драйвера NVIDIA без перезагрузки обесценило CUDA-контекст работающего контейнера, `/health` оставался зелёным, а каждый вызов падал с `CUDA failed with error unknown error`.

Добавлен [scripts/check-conference-service.ps1](../scripts/check-conference-service.ps1): он прогоняет через сервис реальный речевой файл, проверяет, что вернулись слова, и ищет в журнале следы отказов инференса. Отдельно распознаёт состояние «WSL не видит видеокарту» и называет лечение.

Проверено: перезапуска отдельного дистрибутива (`wsl --terminate docker-desktop`) **не хватает**, помогает `wsl --shutdown` — полная остановка виртуальной машины WSL, после которой Windows заново проецирует библиотеки нового драйвера. Перезагрузка Windows не потребовалась.

### Исправления в собственном коде

Независимые адверсарные разборы этой работы нашли и подтвердили дефекты, все исправлены. Наиболее существенные:

- следующая встреча затирала `.md` предыдущей — дескриптор файла подхватывался из IndexedDB автоматически, а запись переписывает файл целиком;
- панель замирала после двойного клика по реплике: перерисовка откладывалась, пока живо выделение, а этот жест выделение оставлял;
- `Illegal invocation` — `setTimeout` хранился в поле объекта и вызывался как метод;
- атрибут `hidden` перебивался собственными правилами `display`, из-за чего постоянно висели блок восстановления и панель выделения;
- «Восстановить» могло заменить идущую запись старой стенограммой.

Тесты расширения: 18 → 66.

## Ограничения и то, чего мы сознательно не делали

- Микрофон записывается (см. второй заход), но **в общий канал вместе со звуком вкладки**. Разделения «я / удалённые участники» нет и не планируется: для задачи важен общий контекст встречи, а не атрибуция реплик. Системный loopback и аудио настольных клиентов по-прежнему не захватываются — только вкладка браузера.
- Расширение работает с WebM-входом WLK. Режим `--pcm-input` для него не включён.
- Метки `Спикер N` приходят от ASR-сервера и не являются гарантированной атрибуцией человека. Текст, имена и специализированные термины нужно проверять перед использованием.
- Модель `large-v3` запущена успешно, но не проводился формальный сравнительный бенчмарк WER/задержки на разрешённой записи конкретных русскоязычных встреч. При высокой занятости 16-гигабайтной GPU возможны нехватка видеопамяти или неприемлемая задержка; практический более быстрый откат — `WLK_MODEL=large-v3-turbo` в `.env` с пересозданием контейнера.
- Не интегрированы GigaAM, T-one, Qwen3-ASR, локальная LLM, MCP-сервер, диаризация по именам или автоматическая постановка задач агенту. Это отдельные этапы, а не скрытая функциональность текущей сборки.
- Нет автозапуска после перезагрузки Windows: текущая политика контейнера `restart=no`. Это сделано осознанно для PoC; запуск описан в операционной инструкции.
- Последняя версия пакета после исправления Brave и добавления шрифтов прошла автоматические проверки, но пока не имеет нового ручного live-подтверждения в браузере. То же относится к Edge: отдельный Edge-тест не проводился.

## Защита данных и эксплуатационные правила

- Не изменяйте публикацию `127.0.0.1:8001` на `0.0.0.0` или адрес локальной сети. У сервиса нет достаточной встроенной сетевой защиты для такого раскрытия.
- Локальность ASR не отменяет требований к уведомлению участников, законному основанию обработки голоса и внутренней политике работы с ПДн, служебной и иной защищаемой информацией.
- Markdown-файл и буфер обмена становятся самостоятельными носителями информации. Назначьте место хранения, права доступа, срок хранения и удаление до использования на рабочих встречах.
- Для корпоративного внедрения зафиксируйте commit, образы, Python/CUDA-зависимости и веса модели в SCA/SBOM-процессе; оцените лицензии и происхождение весов в рамках РБПО по ГОСТ Р 56939-2024.
- Явный экспорт, отсутствие облачного ASR и loopback-публикация уменьшают объём обрабатываемых данных. Они не являются заменой организационным мерам.
- **Микрофон записывается**, если включена соответствующая галочка (по умолчанию выключена). Разрешение выдаётся расширению, а не конференции: отключение микрофона в самой конференции запись расширения не останавливает. Гарантированно прекращают запись только «⏸ Пауза» и «⏹ Завершить».

## С чего продолжить в следующий рабочий день

1. Открыть [операционную инструкцию](LOCAL-CONFERENCE-TRANSCRIPTION-RU.md) и запустить Docker Desktop / Compose.
2. Открыть `brave://extensions` или `chrome://extensions`, нажать **«Обновить»** на карточке unpacked-расширения. Это загрузит исправление завершения и кнопки шрифта. Обновление остановит активный захват, поэтому делать его нужно до встречи.
3. Провести короткий тест на вкладке с разрешённым аудио: открыть панель, закрыть её, открыть снова, нажать «Остановить транскрипцию», дождаться финализации и сохранить `.md`.
4. Лишь после такого теста использовать контур на рабочей встрече с требуемым уведомлением участников и хранить результат в согласованном месте.
